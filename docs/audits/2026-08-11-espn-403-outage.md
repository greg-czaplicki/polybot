# 2026-08-11 — ESPN 403 outage (six-day silent canonical-data freeze)

## Summary

ESPN's WAF began rejecting requests without a `User-Agent` header on or
around **2026-08-06**. Cloudflare Workers' `fetch` sends no User-Agent by
default, so every ESPN call from the worker — scoreboard, summary,
pickcenter — returned **403** for six days. Every failure path returned
`null` and was skipped silently, so `canonical_sync_runs` recorded
`status: success` with zero counts throughout.

Discovered 2026-08-11 while diagnosing why only 10/148 ML picks since
7/23 carried `book_clv`. Fixed same day (`e26c852`), deployed ~23:03 UTC;
recovery confirmed within minutes.

## Impact (2026-08-06 → 2026-08-11)

- **Zero games finalized after 2026-08-04** (partial on 8/4: 5/14).
  `result-ingestion` reported `notFound: 50` every run.
- **Fact computation / team trends frozen at ~8/4 finals.** Picks and
  shadow rows made 8/5–8/11 were scored with trend context up to a week
  stale (trends are a 4th-tier tiebreaker; totals don't consume trends,
  so decision impact is limited but nonzero for ML picks).
- **`espn_event_id` stamping dead** → no `season/week` metadata, and the
  book-odds anchor/close pipeline (which requires the linkage) captured
  nothing.
- **Book closes lost for picks whose games sat unlinked** during the
  window. Games of 8/5–8/7 remain permanently unlinked (outside the
  3-day ingestion lookback at fix time); 8/8 partially (13/20).
- Settlement/grading of picks and shadow rows was NOT affected
  (Polymarket resolution path, independent of ESPN).

## Root cause

1. ESPN tightened WAF rules ~8/6: requests with **no** User-Agent or
   with partial/browser-imitation UAs (`Mozilla/5.0`, `node`,
   `polywhaler/1.0`) get 403; plain HTTP-client UAs (`curl/*`,
   `python-requests/*`, `okhttp/*`) pass. Live-verified 2026-08-11 from
   two networks — UA-based, not IP-based.
2. Our failure handling converted every 403 into a silent skip:
   `fetchEspnScoreboard` returns `null` on `!res.ok`, and the ingestion
   loop's `if (!scoreboard?.events) continue;` treats fetch failure the
   same as an empty slate. The sync step counted `errors: 0`.

## Fix (`e26c852`)

- All ESPN fetches (schedule scoreboard, summary/pickcenter, result
  scoreboard) now send `User-Agent: curl/8.5.0`
  (`ESPN_FETCH_HEADERS` in `espn-schedule-ingestion.ts`).
- A `null` scoreboard now increments the espn-schedule step's `errors`
  count, so a recurrence shows up in `canonical_sync_runs` instead of
  masquerading as success.
- Bonus fix while touching `result-ingestion`: its scoreboard fetch used
  `limit=1000`, which silently collapses college feeds to the Top-25
  view (same bug fixed for schedule ingestion in `b2ea470`); now
  `limit=500` + `groups=80/50`. Without this, most CFB finals would have
  been missed from week 0.

## Verification

- Post-deploy: MLB games 8/8–8/13 linked (8/9+ at 100%), finals
  backfilled for 8/8–8/10 within ~10 minutes, 8/11 slate finalizing
  live. Result-ingestion's 14-day unfinalized-game window covered the
  whole outage, so finals self-healed; only `espn_event_id` linkage for
  8/5–8/7 is permanently lost.
- Zero `[espn-schedule] ... 403` lines in worker tail post-deploy.

## Related pre-existing gap (same investigation)

ML picks 7/23–8/4 mostly lack book anchors for a different reason:
`findGameForPick` didn't prefer ESPN-linked game rows until `b2ea470`
(8/5), so picks attached to Polymarket-created duplicate rows with
`espn_event_id = NULL` and the anchor/close capture had nothing to work
with. Net effect: **book anchor coverage is effectively valid only from
2026-08-11 onward** (10 earlier picks excepted). KNOWN-ISSUES updated.

## Watch items

- ESPN could tighten UA rules again — the `errors` count in the
  espn-schedule step of `canonical_sync_runs` is now the early-warning
  signal (was structurally invisible before).
- Trend-bucket analyses over picks made 8/5–8/11 should treat trend
  context as stale (frozen at 8/4 finals).
